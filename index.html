1. Storage Mechanics: B-Trees vs. LSM Trees

Engine Primitives

Storage engine design is defined by trade-offs between Write Amplification Factor (WAF), Read Amplification Factor (RAF), and Space Amplification Factor (SAF).

Dimension B-Tree / B+Tree (Postgres, InnoDB) LSM Tree (RocksDB, ScyllaDB, Cassandra)
Write Pattern In-place random disk page updates (16KB pages). Uses WAL. Sequential I/O. Appends to RAM MemTable, flushes SSTables.
Read Overhead Fast O(log N). Predictable point lookups. Slower. Checks MemTable & multiple SSTable levels (needs Bloom Filters).
Compaction / Maintenance Minimal maintenance (vacuuming, page split cleanup). High background Compaction I/O (Leveled or Size-Tiered).
Write Amplification High (updating 10 bytes re-writes entire 16KB page). Low initially, but grows during deep level compactions.
Key Formula: Bloom Filter False Positive Rate
$p \approx \left(1 - e^{-kn/m}\right)^k$ where $m$ = bits, $n$ = keys, $k$ = hash functions. Bloom filters prevent disk reads on negative lookups.

2. Distributed Consistency: PACELC & Quorum Math

Distributed Mechanics

While CAP governs behavior during network partitions (P), PACELC governs normal execution (E): If Partition (P), choose Availability (A) or Consistency (C); Else (E), choose Latency (L) or Consistency (C).

PC / EC Systems

Prefers Consistency under partition AND under normal operation.

Examples: Spanner, CockroachDB
PA / EL Systems

Prefers Availability under partition and Low Latency normally.

Examples: Cassandra, DynamoDB
PC / EL Systems

Prefers Consistency under partition, but Low Latency normally.

Examples: MongoDB (Primary Read)
Quorum Consistency Equation

Strong Consistency is guaranteed when Write Quorum ($W$) + Read Quorum ($R$) > Replication Factor ($N$).

W + R > N ==> Overlapping node guarantees reading the latest vector clock / timestamp.

3. Resiliency: Cache Stampede & Single-Flight Defense

High Concurrency

A Cache Stampede (Thundering Herd) occurs when a high-QPS key expires, causing thousands of concurrent worker threads to hit the primary SQL database simultaneously in the same millisecond.

1. Single-Flight Request Coalescing

Intermediary proxy layer catches 10,000 identical incoming requests, issues only 1 query to the DB/Cache, and broadcasts the returned result buffer to all 10,000 callers in memory.

2. XFetch Probabilistic Early Expiration

Probabilistically triggers a background refresh before the cache key dies based on request frequency and remaining TTL.

XFetch Algorithm Formula
Recompute if: -β * δ * ln(random()) > TTL - now

Where β > 0 is a constant multiplier and δ is the delta compute duration in milliseconds.

4. Relational Database Scaling & Connection Management

Scale Primitives

Databases like MySQL allocate a dedicated process/thread per connection. When 10,000 application workers connect directly, memory explodes ($10,000 imes ext{stack buffer}$) and CPU context-switching causes thread starvation.

Vitess Middleware Pattern (YouTube & Slack) gRPC Connection Multiplexing

App servers talk standard SQL to VTGate proxies. VTGate pools and multiplexes 50,000+ incoming app connections down to a tight, persistent pool of gRPC connections managed by VTTablet alongside MySQL.

5. Messaging Logs vs. Task Queues & Geospatial Indexing

Event Infrastructure
Task Queues (RabbitMQ, SQS)
  • Destructive Consumer: Messages deleted post-ack.
  • Non-Replayable: Cannot rewind state history.
  • Worker Pool: Competing consumers process arbitrary tasks.
Commit Logs (Kafka, Cloud Pub/Sub)
  • Immutable Record: Retained by time/size log policy.
  • Replayable: Consumer offset pointers can be rewound.
  • Ordered: Strict FIFO order per partition key.
Geospatial Partitioning: Uber H3 vs. Geohash

2D spatial proximity does not map linearly to a 1D scalar B-Tree. Uber H3 projects hexagonal grid cells onto the globe across 16 resolution levels. Hexagons guarantee equal distances to all 6 adjacent neighbors, eliminating the directional diagonal distortion inherent in square Geohash grids.

6. High-Scale Production Case Studies

Real-World Engineering
Discord: Trillion-Message Storage Engine ScyllaDB + Rust

Replaced 177 Cassandra nodes with 72 ScyllaDB nodes (C++ shard-per-core) to eliminate JVM stop-the-world Garbage Collection pauses. Added a Rust proxy layer performing Single-Flight Request Coalescing to drop P99 latency from 125ms to 15ms.

Slack: Scaling MySQL with Vitess Vitess + gRPC

Migrated monolithic MySQL sharded manually by team_id to Vitess. Abstracted sharding behind VTGate SQL proxies, enabling zero-downtime resharding of 100k+ user enterprise workspaces by (channel_id, user_id).

Google Cloud Spanner: Global Serializability Atomic Clocks + Paxos

Combined TrueTime atomic clock hardware ($\epsilon \le 1 ext{ms}$ drift bounds) with Commit-Wait rules and Multi-Paxos consensus to achieve externally consistent multi-region serializability without locking global reads.
